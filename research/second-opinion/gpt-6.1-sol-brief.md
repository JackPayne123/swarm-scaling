# Second opinion request

## What we're working on
Jack (an AI-safety evals researcher, working independently, budget roughly a few hundred to ~$2k of API spend, one week) wants to write a LessWrong post that is a direct empirical follow-up to Toby Ord's curated post "Swarm Scaling" (LessWrong, 22 Sep 2026). Ord defines λ: N agents working together achieve as much as one agent working N^λ times as long. He estimated λ = 0.68 (BrowseComp), 0.57 (SEC-Bench Pro), 0.48 (Terminal-Bench) by reading GPT-5.6 Sol launch-post charts (1/4/16-agent "ultra mode"), and said nobody has run swarms of different sizes at the same per-agent budget. Commenters argued λ could approach or exceed 1 for creative, verifiable tasks and with heterogeneous agents. Noam Brown (Dwarkesh, 17 Sep 2026) said OpenAI's agents communicate via a send_message tool that injects into the recipient's context, sub-agents get forked context, swarms tend to "collapse to 'we're all just going to solve the problem independently'" (a local minimum), and "we don't have very good science on multi-agent scaling".

### Proposed post: "Where do swarms beat one agent at matched compute?"
Part 1 (day 1, ~free): reanalyse the public data. Fit λ properly from OpenAI's raw chart JSON with CIs (Ord eyeballed charts). Recompute Anthropic's results at matched agent-hours/tokens. Headline table: every public compute-matched comparison so far favours the single agent on tokens; swarms buy wall-clock.

Part 2: new experiment where theory (Park) predicts communication pays.
- Arms at matched total tokens: (1) one agent with per-agent budget b, 2b, 4b, 8b (duration scaling); (2) N = 1,2,4,8 communicating agents at budget b each (swarm scaling) - λ = ratio of slopes; (3) N independent agents (no comms), aggregated by self-selection/voting not oracle, resampled from a pool of single-agent runs at b; (4) optional ablation on a subset: shared directory only, no messaging (Park's design vs lab designs).
- Harness: Inspect (UK AISI). N agents run concurrently inside one sample, shared sandbox filesystem/git, custom send_message(to, text) tool (to = agent or "all") whose messages are drained into each agent's context before every model call, plus wait_for_message(timeout). Fixed N, one designated lead, otherwise flat (no spawning, so N stays fixed for compute matching). Per-agent token_limit. Incoming messages count against recipient's tokens.
- Metrics: λ with bootstrap CIs; decomposition of swarm gain into parallel sampling (independent arm) vs communication (comm minus independent); collapse rate (share of comm teams whose logs show no agent using another's work); wall-clock speedup; for AlgoTune an LLM classification of final solutions as algorithmic vs surface-level change.
- Task families: (a) ProgramBench (public, rebuild codebase from binary+docs, score = fraction of hidden tests passed; Anthropic matched-token baseline exists; Sonnet uses ~1.3M tokens/task at 4h) - decomposable building; (b) AlgoTune (NeurIPS 2025, 154 CPU numerical tasks, score = speedup vs SciPy/sklearn/CVXPY reference, authors found models prefer surface-level optimisations over algorithmic innovation) - creative optimisation. Score AlgoTune solutions afterwards serially on an idle machine to avoid timing contamination from concurrent agents. Rejected: Terminal-Bench (66 pass/fail tasks, OpenAI already has data), BrowseComp/DRACO/WANDR (search; Jack finds it uninteresting), FrontierSWE (~20h/task), PostTrainBench/NanoGPT (H100-hours), MLE-Bench (heavy), ITBench (k8s setup), cyber/bio (containment, hazard), private evals.
- Models: main grid on GLM-5.3-Flash ($0.15/$0.50 per 1M; AA intelligence 41.8), replication subset on Sonnet 5.5 ($2/$10; 56). Caveat: coordination is a trained behaviour tied to each lab's native tool; a custom tool may under-elicit. Optional check: small GPT-6.1 Sol arm on OpenAI's hosted multi-agent API (native tools, but dynamic spawning so not exactly compute matched).
- NEW, Jack's hypothesis: mixed-model swarms. Most of the gain may come from heterogeneity (Ord commenter quoting a mathematician who solved Pierce-Birkhoff on $400: one agent per model family beat a larger same-model swarm; Julian Bradshaw argues homogeneity is what drags λ down). Labs can't/won't publish cross-vendor swarms, so it's an independent-researcher angle. Price-matched pairs exist: cheap tier GLM-5.3-Flash ($0.15/$0.50, AA 41.8) + GPT-6 Luna ($0.10/$0.50, AA 38.1); frontier tier Sonnet 5.5 ($2/$10, AA 56) + GPT-6.1 Sol ($2/$10, AA 51.8). Equal prices make dollar matching ~ token matching (tokenizers differ). Draft design: homogeneous A, homogeneous B, mixed communicating, mixed independent, all at matched dollars; complementarity = mixed-comm > max(homo-A, homo-B); diversity-only = mixed-independent > homogeneous-independent.

## What I'm unsure about
- Whether matched-token λ on cheap models in a custom harness says anything about frontier swarms, given coordination is trained per-lab.
- Whether the post is too broad (reanalysis + two task families + mixed models + ablation) for one week, and which piece to make the headline. Leaning: mixed-model may be the most novel headline; λ reanalysis the cheapest solid result.
- Whether ProgramBench's ceiling (Sonnet single agent already 0.92 at 4h) kills it as a measurement instrument unless we use a harder subset or a weaker model.
- Whether self-selection/voting for the independent arm is fair for continuous-score tasks (for AlgoTune you could just take the fastest correct solution since correctness is checkable - is that oracle or legitimate?).
- Whether "compute" should be matched by tokens, dollars, or both, especially in the mixed arm.
